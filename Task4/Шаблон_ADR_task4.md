**Логика принятия решений**
1. Для обновления данных по актуальным ставкам в системе кол-центра предлагается использовать брокер сообщений, реализуемый для этапа MVP.
2. Для обновления данных по актуальным ставкам в системе партнерского кол-центра предлагается использовать обновление файла через протокол SFTP, т.к. партнерский КЦ не может вызывать апи.
### <a name="_bjrr7veeh80c"></a>**Альтернативы**
1. Прямое обращение системы кол-центра в АБС. Отклонено, т.к. система АБС перегружена, высок риск отказа системы.
2. Прямое обращение системы партнерского кол-центра в АБС. Отклонено, т.к. система партнерского КЦ не может вызывать апи, а также высок риск отказа АБС.

**Недостатки, ограничения, риски**

**Недостатки**
1. Необходимость развертывания SFTP-сервера в системе партнерского КЦ.
2. У команд разработки нет опыта интеграции через брокер сообщений kafka.
3. Возможные задержки в обновлении данных по ставкам

**Ограничения**
1. Невозможность вызывать апи системой партнерского КЦ.

**Риски**
1. В случае отказа FTP-сервера партнерский КЦ теряет доступ к актуальным данным по ставкам.
