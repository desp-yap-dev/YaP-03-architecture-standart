**Основные компоненты: </b>**
1. **Сайт**
- стек - React
- интеграция с апи АБС для получения информации по актуальным депозитам
- интеграция с системой кол-центра для передачи заявок на депозит

2. **Интернет-банк**
- стек - ASP.NET + React + MS SQL
- семейство микросервисов для управления депозитами, счетами
- интеграция с АБС через брокер сообщений
- интеграция с смс-шлюзом для отправки смс

3. **АБС**
- стек - Delphi + Oracle + Redis
- клиентское приложение для сотрудников
- кэш справочных данных
- брокер сообщений для обработки заявок 

4. **Система кол-центра**
- стек - Java
- поддерживается подрядчиком
- интеграция с АБС для передачи информации по заявкам на депозиты через брокер сообщений

5. **Смс-шлюз**
- стек - ASP.NET
- интеграция со внешним телеком-сервисом

Также опишите, какой логикой вы руководствовались в ходе принятия решений и выбора технологий. Не забывайте, что необходимо учесть все функциональные и нефункциональные требования.

**Логика принятия решений**
1. Интернет-банк представляет собой семейство микросервисов. При недоступности сервиса депозитов информация о счетах будет доступна. В будущем позволит масштабироваться горизонтально при увеличении количества клиентов и RPS.
2. Для реализации сервисов выбран стек технологий, знакомый команде разработки.
3. Брокер сообщений в АБС. Покрывает требование отсутствия прямой интеграции интернет-банка с АБС, позволит избежать высокой нагрузки.
4. Выделен кэш справочных данных. Позволит ускорить загрузку справочников.
5. Смс-шлюз. Будет разработан силами команды разработки банка для устранения зависимости от доработок ядра системы подрядчика. 
### <a name="_bjrr7veeh80c"></a>**Альтернативы**

1. Прямая работа интернет-банка с АБС. Отклонено, т.к., во-первых, противоречит требованиям, а во-вторых, в случае, если большое количество заявок приведет к неработоспособности АБС, встанет работа банка.
2. Отсутствие кэша в АБС. Может привести к длительным операциям получения данных и перегрузить базу данных АБС.

**Недостатки, ограничения, риски**

**Недостатки**
1. Обработка заявок происходит в ручном режиме менеджерами депозитов и кредитования.
2. Требуется разработка большого количества сервисов, нужна оценка и проработка роадмапа, чтобы уложиться в сроки MVP. Возможно, разработку части-сервисов интернет-банка нужно отложить на второй этап.
3. Узкое место - база данных АБС. Возможно, потребуется вертикальное масштабирование.

**Ограничения**
1. Использование стека технологий, принятого в банке.

**Риски**
1. Отсутствие у команды опыта работы с Kafka
2. Риск не уложиться в сроки MVP
